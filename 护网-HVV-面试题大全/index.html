护网（HVV）面试题大全

网络安全 红队 HVV 护网 面试题 应急响应 蓝队
网络安全
发布日期:   2026-06-04

本文综合整理了护网（HVV）面试中常见的技术问题，覆盖应急响应、流量分析、漏洞攻防、安全设备、网络基础等多个维度，适合蓝队、红队及安全运营方向的同学参考。

一、应急响应

1. 应急响应的标准流程是什么？

答： 六步法——收集信息 → 判断类型 → 抑制范围 → 深入分析 → 清理处置 → 输出报告。

  1. 收集信息： 收集客户信息和中毒主机信息，包括样本
  2. 判断类型： 判断是否为安全事件及类型（勒索、挖矿、断网、DoS 等）
  3. 抑制范围： 隔离受害面，防止继续扩大
  4. 深入分析： 日志分析、进程分析、启动项分析、样本分析，便于溯源
  5. 清理处置： 杀进程、删文件、打补丁、删异常服务和后门账号，恢复生产
  6. 输出报告： 整理完整安全事件报告

2. Windows 入侵排查思路？

答：

  • 账号安全： 查弱口令、远程管理端口是否对公网开放（netstat -ano）；lusrmgr.msc 查可疑/新增账号；D 盾查隐藏账号、克隆账号；日志查管理员登录异常
  • 异常端口/进程： netstat -ano 检查端口连接，任务管理器查进程
  • 启动项/计划任务/服务： 检查是否有异常自启动项
  • 系统信息： 系统版本、补丁情况、可疑目录及文件
  • 日志分析： eventvwr.msc 导出安全日志，用 Log Parser 分析

3. Linux 入侵排查思路？

答：

  • 账号安全： who/w/uptime 查登录用户；/etc/passwd 和 /etc/shadow 检查用户信息
  • 历史命令： .bash_history 查看执行过的命令
  • 异常端口： netstat -antlp | more，ls -l /proc/$PID/exe 查进程文件路径
  • 异常进程： ps aux | grep pid
  • 开机启动项： /etc/rc.local、/etc/rc.d/rc[0~6].d
  • 定时任务： crontab -l，文件在 /var/spool/cron/用户名
  • 服务： chkconfig --list
  • 异常文件和系统日志

4. 挖矿病毒如何判断和处理？

答：

判断特征： 系统响应缓慢、CPU/显卡使用率过高、内存/带宽占用高

确认方式： 查看进程（注意系统命令可能被替换）、检查日志和系统用户、发现异常文件

常见入侵手段：

  • 未授权访问或弱口令（Redis、Docker API、Hadoop Yarn、SSH 等）
  • 远程命令执行漏洞（WebLogic、Jenkins、Struts2、永恒之蓝等）

清除流程：

  1. 及时隔离主机（防蠕虫横向传播）
  2. iptables 阻断与矿池通讯
  3. 清除定时任务
  4. 清除启动项
  5. 先杀守护进程再杀挖矿进程
  6. 清除 .ssh/authorized_keys 中的可疑公钥

5. 大范围 0day 被曝光，甲方安全工程师如何处理？

答：

  1. 评估影响： 分析 0day 对自身系统的影响（利用点、是否需交互、是否影响 CIA、是否有在野 PoC、资产是否暴露公网等，参考 CVSS 评分）
  2. 建立感知： 确定有影响且有 PoC 时，分析 PoC 执行痕迹位置，利用现有设备采集数据，编写对应检测规则，用 SIEM 或实时日志分析平台建立感知防线
  3. 纵深防御： 日常建立完整纵深防御体系，不依赖单一防线

6. DDoS/CC 攻击如何发现和应急？

答：

发现方法：

  • 部署流量监视/审计系统，设立警戒阈值
  • Linux 日志（dmesg/message）记录 Flood 日志
  • netstat 统计连接数，top 查看资源使用
  • tcpdump/tshark 抓包分析

应急措施：

  • 低网络层 DDoS：丢弃第一次 SYN 包、上流量防护设备、上 WAF 封禁地址
  • CC 攻击：优化代码、增加硬件、上云 WAF/CDN/负载均衡、隐藏真实 IP
  • 购买运营商流量清洗服务（最有效）

二、流量分析与研判

7. 蓝队研判工作怎么做？

答：

  1. 充分利用已有安全设备，分析近期告警
  2. 将全部流量日志（源地址、目的地址、端口、事件名称、时间等）根据研判标准筛选
  3. 挖矿、蠕虫、病毒、拒绝服务等不太可能为攻击方发起的事件直接过滤
  4. 真实攻击通常是长时间、周期性、多 IP 进行的
  5. 结合威胁情报库（微步、奇安信、绿盟）对源 IP 分析
  6. 分析请求数据包和返回数据包判断是否误报
  7. 留意 X-Forwarded-For 和 x-real-ip 字段
  8. 了解 Webshell 工具流量特征
  9. 上报时提供完整截图：源 IP、目的 IP、请求包、响应包等

8. Webshell 管理工具的流量特征？

答：

工具 特征
菜刀 url 编码 + base64 编码，参数名 z0，存在 int_set("display_errors","0") 特征
蚁剑 默认连接请求两次（第一次获取主机信息，第二次列目录），请求体经 url 编码
冰蝎 2.0 AES 加密三次请求：第一次产生密钥写入 session，第二次获取 key，第三次 AES 加密通信
冰蝎 3.0 AES 加密两次请求，连接密码 MD5 前 16 位作密钥
哥斯拉 支持多种加密，建立连接发起三次请求，第一次数据超长建立 session

9. 如何检测 Webshell？

答：

主机层面：

  • 静态检测： 匹配特征码、危险函数（eval、assert、system 等）
  • 动态检测： 监控系统调用、文件操作
  • 日志检测： web 日志中查找 webshell 页面访问数据
  • 语法检测： 语法语义分析，剥离注释，分析变量和函数

流量层面： 分析请求/响应特征，加密通信模式

排查命令：

find /var/www/html -name "*.php" | xargs egrep 'assert|eval|phpinfo\(\)|base64_decode|shell_exec|passthru|file_put_contents'

10. 数据包或日志分析思路？

答：

  1. 用流量监测设备（如天眼）查看报文
  2. 分析 host 和网站目录路径是否可疑
  3. 使用微步等威胁情报查询 host/IP 是否恶意
  4. 用 Wireshark 深度分析数据包
  5. 看请求路径、源 IP 与目的 IP、host 字段值、发包内容
  6. 分析请求数据包和返回数据包判断攻击是否成功

三、常见漏洞与攻击

11. SQL 注入如何检测和加固？

答：

检测：

  • 入侵前：对 Payload 进行规则匹配检测
  • 入侵后：检查数据库、IIS/Apache 日志
  • 传统方法基于规则库匹配，也可采用机器学习方式

加固措施：

  • 对输入字符进行过滤和转义
  • 使用 PDO 预编译语句/参数化查询
  • 最小权限原则配置数据库账号
  • WAF 规则防护

12. 文件上传漏洞原理及加固？

答：

原理： 应用程序对用户上传文件类型不校验或校验不严格可绕过，导致攻击者上传 webshell 获取服务器权限。

加固方法：

  1. 后端限制文件上传白名单
  2. 上传后文件随机重命名，不输出保存路径
  3. 图片文件二次渲染，使用对象存储 OSS
  4. 文件目录取消执行权限
  5. PHP 设置 basedir 限制

13. 常见中间件漏洞有哪些？

答：

中间件 常见漏洞
IIS PUT 漏洞、短文件名猜解、远程代码执行、解析漏洞
Apache 解析漏洞、目录遍历
Nginx 文件解析、目录遍历、CRLF 注入、目录穿越
Tomcat 远程代码执行、war 后门部署
JBoss 反序列化漏洞、war 后门部署
WebLogic 反序列化、SSRF、任意文件上传、war 后门

14. 常见端口对应的漏洞？

答：

数据库类（弱口令）：

  • 1433：MSSQL | 1521：Oracle | 3306：MySQL | 5432：PostgreSQL

特殊服务类（未授权/命令执行）：

  • 6379：Redis 未授权 | 7001/7002：WebLogic | 8088：Hadoop Yarn 未授权
  • 9200/9300：Elasticsearch 命令执行 | 11211：Memcache 未授权
  • 27017：MongoDB 未授权 | 443：SSL 心脏滴血 | 873：Rsync 未授权

常用端口类：

  • 21：FTP 弱口令 | 22：SSH | 23：Telnet | 445：SMB（ms17-010）| 3389：RDP

15. Fastjson 漏洞利用原理？

答：

程序处理 JSON 对象时未对 @type 字段进行过滤，攻击者可传入恶意的 TemplatesImpl 类。该类有 _bytecodes 字段，部分函数会根据此字段生成 Java 实例，在类实例化时执行构造函数，实现代码执行。

不出网利用方式：

  • 将命令执行结果写入静态资源文件，通过 HTTP 访问查看
  • 通过 dnslog 进行数据外带
  • 将结果直接回显到 HTTP 响应中

四、红队/渗透相关

16. 外围打点的基本流程？

答：

  1. 靶标确认： 明确目标范围
  2. 信息收集： 子域名、Whois、C 段、旁站、Web 指纹识别
  3. 漏洞探测： 扫描 + 手工测试
  4. 利用漏洞： 优先 Java 反序列化类（Shiro、Fastjson、WebLogic、用友 OA 等）
  5. 获取权限： 获取靶标系统权限和关键数据

17. 横向渗透有哪些命令执行手段？

答：

  • psexec
  • wmic
  • smbexec
  • winrm
  • net use 共享 + 计划任务 + type 命令

18. 域内攻击方法有哪些？

答：

  • MS14-068（域提权）
  • Roasting 攻击（离线爆破密码）
  • 委派攻击（非约束性委派）
  • 基于资源的约束委派
  • NTLM Relay
  • 域委派：把域内用户权限委派给服务账户，让服务账号能以该用户身份在域内活动

19. 不出网情况下如何处理？

答：

  • 使用 socks 隧道
  • CS（Cobalt Strike）直接上线
  • ICMP 隧道（封装数据到 Ping 包）
  • DNS 隧道（通过 DNS 查询传递数据，企业极少封锁 DNS 端口）

20. 木马免杀有哪些方式？

答：

  1. 代码混淆： 加密字符串（AES）、指令重排
  2. 加壳： UPX 压缩或 VMProtect 虚拟化
  3. 内存加载： PE 文件注入合法进程（最有效，不落盘且行为模拟合法进程）
  4. 签名劫持： 伪造微软签名或劫持白名单程序

21. 如何绕过 WAF？

答：

  1. 编码绕过： Unicode/Base64 编码注入语句
  2. 分块传输： HTTP 协议分块发送恶意载荷（绕过正则匹配）
  3. IP 轮替： 代理池切换源 IP 避开速率限制
  4. 利用 WAF 规则盲区： 如 JSON 格式 SQLi
  5. 参数污染、大小写混合、注释符干扰

22. 如何识别 CDN 并找到真实 IP？

答：

识别 CDN：

  • ping 命令观察回显（是否有 CDN 节点域名）
  • nslookup 查询域名解析
  • 超级 ping 工具查看多地解析结果是否一致

绕过 CDN 找真实 IP：

  • 查询历史 DNS 解析记录
  • 子域名可能未使用 CDN
  • 邮件服务器 IP
  • 国外节点访问
  • SSL 证书信息

24. 护网的分组和流程？

答：

分组： 领导小组下分防护检测组、综合研判组、应急溯源组

三阶段流程：

  • 备战阶段： 资产梳理、减少暴露面、漏洞扫描、渗透测试、弱口令自查
  • 临战阶段： 内部演练发现疏忽并整改；增加安全设备（WAF、IPS、IDS、SOC、堡垒机）
  • 决战阶段： 坚守岗位，看应急日志，不能解决就上报，持续优化防护

25. 护网期间蓝队日常工作内容？

答：

核心四项：监控、研判、处置、溯源

具体工作：

  • 使用 IPS/IDS 等设备做流量监控与日志分析
  • 判断安全事件是否误判
  • 对安全管理中心发出的态势排查单进行排查并反馈
  • 执行封堵/解封工单
  • 每两小时反馈排查结果、设备巡检报告、封堵情况

六、网络基础

26. TCP 三次握手与四次挥手？

答：

三次握手：

  1. 客户端发送 SYN → SYN_SENT
  2. 服务器回 SYN+ACK → SYN_RCVD
  3. 客户端发 ACK → 双方 ESTABLISHED

四次挥手：

  1. 客户端发 FIN → FIN_WAIT_1
  2. 服务端回 ACK → CLOSE_WAIT
  3. 服务端发 FIN → LAST_ACK
  4. 客户端回 ACK → TIME_WAIT → CLOSED

27. HTTP 无连接与无状态的含义？

答：

  • 无连接： 每次连接只处理一个请求，处理完收到应答后断开（HTTP/1.1 引入 Keep-Alive 改善）
  • 无状态： 协议对事务处理没有记忆能力，每次请求独立，服务器不保存客户端状态（通过 Cookie/Session 解决）

28. 同源策略与跨域？

答：

  • 同源策略： 域名、协议、端口均相同才算同源
  • 跨域： 浏览器不能执行其它源的脚本，由同源策略造成
  • JSONP： 利用 script 标签 src 属性可跨域，只支持 GET
  • CORS： 支持所有 HTTP 请求类型，通过服务端设置 Access-Control-Allow-Origin 实现

七、安全加固

29. Linux 安全加固要点？

答：

  1. 关闭不必要系统服务
  2. 更改 SSH 默认端口，禁止 root 远程登录
  3. 限制 su 切换 root
  4. 密码复杂度策略（/etc/login.defs）
  5. 检查空口令账号
  6. 禁止 ctrl+alt+del 重启
  7. 禁用 telnet，用 ssh 替代
  8. 设置 hosts.allow 和 hosts.deny
  9. iptables + denyhost 防 SSH 暴力破解
  10. 设置 umask 值 027，登录超时 TMOUT=180

30. Windows 安全基线检查五方面？

答：

  1. 身份鉴别： 更改缺省账户、禁用 Guest、密码复杂性、最小 8 位
  2. 访问控制： 共享账户检查、远程关机授权、授权登录
  3. 安全审计： 登录日志记录、系统日志完备性
  4. 资源控制： 登录超时管理、远程登录超时配置
  5. 剩余信息保护： 不显示上次用户名、关机前清除虚拟内存

八、综合场景题

31. 内网横向攻击如何处理？

答：

  1. 确定攻击来源（是否员工误操作/自动化脚本）
  2. 确定是攻击后，结合时间点查看设备信息、安全事件、进程、流量
  3. 找到问题主机
  4. 应急响应流程：准备 → 检测 → 遏制 → 根除 → 恢复 → 跟踪

32. 如何判断服务器是否被入侵？

答：

网站被攻击表现： 跳转赌博网站、首页被篡改、百度快照被改、被植入 webshell、被 DDoS/CC

服务器被黑表现： 中木马病毒、管理员密码被改、被远程控制、带宽向外发包

排查方法： 分析登录记录、系统日志、web 日志、进程列表、网络连接、启动项

33. Java 内存马如何排查？

答：

  • JSP 注入： 日志中排查可疑 jsp 访问请求
  • 代码执行漏洞： 排查中间件 error.log 可疑报错
  • Servlet/Spring controller 类型： 根据 url 查找日志，确定最早访问时间即注入时间
  • Filter/Listener 类型： 可能有较多 404 带参数请求，或大量不同 url 带相同参数，或页面不存在但返回 200

34. 文件读取漏洞通常读哪些文件？

答：

Linux：

  • /etc/passwd、/etc/shadow
  • /root/.bash_history
  • /root/.ssh/id_rsa（拿私钥直接 ssh）
  • /proc/xxxx/cmdline（进程状态枚举）
  • 数据库 config 文件、web 日志

Windows：

  • C:\boot.ini（系统版本）
  • C:\Windows\System32\inetsrv\MetaBase.xml（IIS 配置）
  • C:\Windows\repair\sam（系统初次安装密码）
  • C:\Program Files\mysql\my.ini（MySQL 配置）

35. TLS 加密过程简述？

答：

  1. 客户端发送随机数 1 和支持的加密算法列表
  2. 服务端确定加密算法，发送随机数 2
  3. 服务端发送数字证书（含公钥），客户端验证证书有效性
  4. 客户端生成随机数 3，用公钥加密后发送给服务端
  5. 双方用三个随机数通过 DH 算法生成对称密钥
  6. 后续通信使用对称密钥加密

九、常用工具

36. 常见安全工具有哪些？

答：

类别 工具

十、企业安全运营

37. 什么是企业安全运营？如何建设？

答：

定义： 以资产为核心、以安全事件管理为关键流程，建立实时资产风险模型，协助进行事件分析、风险分析、预警管理和应急响应的集中安全管理体系。

建设方向：

  1. 合规性建设： 等级保护、风险评估、制度体系
  2. 组织架构建设： 明确安全职责矩阵
  3. 安全运营服务体系： 基线加固、运维审计、攻防演练、态势监测、漏洞管理
  4. 安全管理服务： 制度管理、流程管理、人员管理、培训管理

38. 如何降低被蓝队发现的概率？（红队视角）

答：

  • 侦查阶段： 使用匿名基础设施（Tor + 云虚拟机）
  • 攻击阶段： 无文件攻击 + 合法工具滥用（Living-off-the-Land）
  • 持久化： 隐藏计划任务/注册表键（命名仿系统服务）
  • 核心原则： 减少攻击频率，模拟正常用户行为（如工作时间访问）
