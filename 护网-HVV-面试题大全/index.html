护网（HVV）面试题大全

网络安全 红队 HVV 护网 面试题 应急响应 蓝队
网络安全
发布日期:   2026-06-04

本文综合整理了护网（HVV）面试中常见的技术问题，覆盖应急响应、流量分析、漏洞攻防、安全设备、网络基础等多个维度，适合蓝队、红队及安全运营方向的同学参考。

一、应急响应

1. 应急响应的标准流程是什么？

答： 六步法——收集信息 → 判断类型 → 抑制范围 → 深入分析 → 清理处置 → 输出报告。

  1. 收集信息： 收集客户信息和中毒主机信息，包括样本
  2. 判断类型： 判断是否为安全事件及类型（勒索、挖矿、断网、DoS 等）
  3. 抑制范围： 隔离受害面，防止继续扩大
  4. 深入分析： 日志分析、进程分析、启动项分析、样本分析，便于溯源
  5. 清理处置： 杀进程、删文件、打补丁、删异常服务和后门账号，恢复生产
  6. 输出报告： 整理完整安全事件报告

2. Windows 入侵排查思路？

答：

  • 账号安全： 查弱口令、远程管理端口是否对公网开放（netstat -ano）；lusrmgr.msc 查可疑/新增账号；D 盾查隐藏账号、克隆账号；日志查管理员登录异常
  • 异常端口/进程： netstat -ano 检查端口连接，任务管理器查进程
  • 启动项/计划任务/服务： 检查是否有异常自启动项
  • 系统信息： 系统版本、补丁情况、可疑目录及文件
  • 日志分析： eventvwr.msc 导出安全日志，用 Log Parser 分析

3. Linux 入侵排查思路？

答：

  • 账号安全： who/w/uptime 查登录用户；/etc/passwd 和 /etc/shadow 检查用户信息
  • 历史命令： .bash_history 查看执行过的命令
  • 异常端口： netstat -antlp | more，ls -l /proc/$PID/exe 查进程文件路径
  • 异常进程： ps aux | grep pid
  • 开机启动项： /etc/rc.local、/etc/rc.d/rc[0~6].d
  • 定时任务： crontab -l，文件在 /var/spool/cron/用户名
  • 服务： chkconfig --list
  • 异常文件和系统日志

4. 挖矿病毒如何判断和处理？

答：

判断特征： 系统响应缓慢、CPU/显卡使用率过高、内存/带宽占用高

确认方式： 查看进程（注意系统命令可能被替换）、检查日志和系统用户、发现异常文件

常见入侵手段：

  • 未授权访问或弱口令（Redis、Docker API、Hadoop Yarn、SSH 等）
  • 远程命令执行漏洞（WebLogic、Jenkins、Struts2、永恒之蓝等）

清除流程：

  1. 及时隔离主机（防蠕虫横向传播）
  2. iptables 阻断与矿池通讯
  3. 清除定时任务
  4. 清除启动项
  5. 先杀守护进程再杀挖矿进程
  6. 清除 .ssh/authorized_keys 中的可疑公钥

5. 大范围 0day 被曝光，甲方安全工程师如何处理？

答：

  1. 评估影响： 分析 0day 对自身系统的影响（利用点、是否需交互、是否影响 CIA、是否有在野 PoC、资产是否暴露公网等，参考 CVSS 评分）
  2. 建立感知： 确定有影响且有 PoC 时，分析 PoC 执行痕迹位置，利用现有设备采集数据，编写对应检测规则，用 SIEM 或实时日志分析平台建立感知防线
  3. 纵深防御： 日常建立完整纵深防御体系，不依赖单一防线

6. DDoS/CC 攻击如何发现和应急？

答：

发现方法：

  • 部署流量监视/审计系统，设立警戒阈值
  • Linux 日志（dmesg/message）记录 Flood 日志
  • netstat 统计连接数，top 查看资源使用
  • tcpdump/tshark 抓包分析

应急措施：

  • 低网络层 DDoS：丢弃第一次 SYN 包、上流量防护设备、上 WAF 封禁地址
  • CC 攻击：优化代码、增加硬件、上云 WAF/CDN/负载均衡、隐藏真实 IP
  • 购买运营商流量清洗服务（最有效）

二、流量分析与研判

7. 蓝队研判工作怎么做？

答：

  1. 充分利用已有安全设备，分析近期告警
  2. 将全部流量日志（源地址、目的地址、端口、事件名称、时间等）根据研判标准筛选
  3. 挖矿、蠕虫、病毒、拒绝服务等不太可能为攻击方发起的事件直接过滤
  4. 真实攻击通常是长时间、周期性、多 IP 进行的
  5. 结合威胁情报库（微步、奇安信、绿盟）对源 IP 分析
  6. 分析请求数据包和返回数据包判断是否误报
  7. 留意 X-Forwarded-For 和 x-real-ip 字段
  8. 了解 Webshell 工具流量特征
  9. 上报时提供完整截图：源 IP、目的 IP、请求包、响应包等

8. Webshell 管理工具的流量特征？

答：

工具 特征
菜刀 url 编码 + base64 编码，参数名 z0，存在 int_set("display_errors","0") 特征
蚁剑 默认连接请求两次（第一次获取主机信息，第二次列目录），请求体经 url 编码
冰蝎 2.0 AES 加密三次请求：第一次产生密钥写入 session，第二次获取 key，第三次 AES 加密通信
冰蝎 3.0 AES 加密两次请求，连接密码 MD5 前 16 位作密钥
哥斯拉 支持多种加密，建立连接发起三次请求，第一次数据超长建立 session

9. 如何检测 Webshell？

答：

主机层面：

  • 静态检测： 匹配特征码、危险函数（eval、assert、system 等）
  • 动态检测： 监控系统调用、文件操作
  • 日志检测： web 日志中查找 webshell 页面访问数据
  • 语法检测： 语法语义分析，剥离注释，分析变量和函数

流量层面： 分析请求/响应特征，加密通信模式

排查命令：

find /var/www/html -name "*.php" | xargs egrep 'assert|eval|phpinfo\(\)|base64_decode|shell_exec|passthru|file_put_contents'

10. 数据包或日志分析思路？

答：

  1. 用流量监测设备（如天眼）查看报文
  2. 分析 host 和网站目录路径是否可疑
  3. 使用微步等威胁情报查询 host/IP 是否恶意
  4. 用 Wireshark 深度分析数据包
  5. 看请求路径、源 IP 与目的 IP、host 字段值、发包内容
  6. 分析请求数据包和返回数据包判断攻击是否成功

11. 冰蝎 3.0 与 4.0 的区别？

答：

维度 冰蝎 3.0 冰蝎 4.0
密钥协商 固定密钥（连接密码 MD5 前 16 位） 动态密钥协商，首次请求交换公钥
通信加密 AES 加密两次请求 AES 加密，后续流量加密随机性更强
流量特征 Content-Type 为 application/octet-stream，请求体长度固定约 1KB 无明显固定长度特征，通信特征更接近正常业务请求
内存马支持 有限 支持内存马，插件生态更丰富
研判重点 看固定入口文件的持续 POST、高熵请求体 需结合异常进程、文件改动、会话行为关联判断

12. 哥斯拉、蚁剑、菜刀的详细流量特征？

答：

哥斯拉 Godzilla：

  • 加密通信（AES），POST 交互，流量伪装能力强
  • 请求体高熵、参数结构固定但内容不可读
  • 可能伪装成正常业务路径或常见 Header
  • Cookie 中可能包含 pass= 开头参数，末尾常多出一个分号
  • 研判需结合固定后门文件、异常回连、文件写入、命令执行综合判断

蚁剑 AntSword：

  • POST 请求、参数编码、Base64 相关内容
  • 常见特征：@ini_set("display_errors","0");@set_time_limit(0) 开头
  • 关键函数：eval、assert、base64_decode
  • 对文件管理、命令执行、数据库操作的交互比较明显
  • 响应体返回结果是 base64 编码发混淆字符，格式为：随机数+结果+随机数

菜刀 Chopper：

  • 老式 WebShell 管理工具，流量相对简单
  • 请求体包含 z0、z1、z2 三个参数，z0 为 Base64 编码的执行命令
  • 可能出现固定连接密码参数，频繁访问同一个后门文件
  • 响应中出现目录、文件、命令执行结果
  • 短连接、单次请求执行单个命令

13. Cobalt Strike（CS）流量特征？

答：

  • Beacon 周期性心跳： 固定或带 jitter 的访问间隔，同一主机周期性访问同一外部 IP/域名
  • User-Agent： 可能伪装，但 JA3/JA3S 指纹异常
  • 请求体/响应体： 加密高熵，数据包大小相近
  • URI 模式： 固定 URI/Header 模式，可能伪装成图片、JS、CDN、API 请求
  • 主机联动证据： rundll32、regsvr32、powershell、wmic、mshta 异常执行，远程服务创建、计划任务、进程注入、凭据访问和横向移动

14. SQL 注入告警如何分析？

答：

分析步骤：

  1. 确定攻击源和目标接口
  2. 对比正常请求，检查参数是否异常
  3. 检查响应状态码、响应长度、报错信息、时间延迟
  4. 查看应用和数据库日志
  5. 判断是真实攻击、扫描探测还是误报（开发测试流量、安全扫描器）

成功证据：

  • 数据库报错、响应长度明显变化
  • 敏感字段回显、时间延迟稳定出现
  • 后续出现枚举库表字段行为

三、常见漏洞与攻击

11. SQL 注入如何检测和加固？

答：

检测：

  • 入侵前：对 Payload 进行规则匹配检测
  • 入侵后：检查数据库、IIS/Apache 日志
  • 传统方法基于规则库匹配，也可采用机器学习方式

加固措施：

  • 对输入字符进行过滤和转义
  • 使用 PDO 预编译语句/参数化查询
  • 最小权限原则配置数据库账号
  • WAF 规则防护

12. 文件上传漏洞原理及加固？

答：

原理： 应用程序对用户上传文件类型不校验或校验不严格可绕过，导致攻击者上传 webshell 获取服务器权限。

加固方法：

  1. 后端限制文件上传白名单
  2. 上传后文件随机重命名，不输出保存路径
  3. 图片文件二次渲染，使用对象存储 OSS
  4. 文件目录取消执行权限
  5. PHP 设置 basedir 限制

13. 常见中间件漏洞有哪些？

答：

中间件 常见漏洞
IIS PUT 漏洞、短文件名猜解、远程代码执行、解析漏洞
Apache 解析漏洞、目录遍历
Nginx 文件解析、目录遍历、CRLF 注入、目录穿越
Tomcat 远程代码执行、war 后门部署
JBoss 反序列化漏洞、war 后门部署
WebLogic 反序列化、SSRF、任意文件上传、war 后门

14. 常见端口对应的漏洞？

答：

数据库类（弱口令）：

  • 1433：MSSQL | 1521：Oracle | 3306：MySQL | 5432：PostgreSQL

特殊服务类（未授权/命令执行）：

  • 6379：Redis 未授权 | 7001/7002：WebLogic | 8088：Hadoop Yarn 未授权
  • 9200/9300：Elasticsearch 命令执行 | 11211：Memcache 未授权
  • 27017：MongoDB 未授权 | 443：SSL 心脏滴血 | 873：Rsync 未授权

常用端口类：

  • 21：FTP 弱口令 | 22：SSH | 23：Telnet | 445：SMB（ms17-010）| 3389：RDP

15. Fastjson 漏洞利用原理？

答：

程序处理 JSON 对象时未对 @type 字段进行过滤，攻击者可传入恶意的 TemplatesImpl 类。该类有 _bytecodes 字段，部分函数会根据此字段生成 Java 实例，在类实例化时执行构造函数，实现代码执行。

不出网利用方式：

  • 将命令执行结果写入静态资源文件，通过 HTTP 访问查看
  • 通过 dnslog 进行数据外带
  • 将结果直接回显到 HTTP 响应中

16. SpringBoot 常见漏洞有哪些？

答：

指纹信息：

  • 响应头：Server: Apache-Coyote 或 X-Application-Context
  • 默认错误页面特征、Wappalyzer 指纹识别

常见漏洞：

  • Actuator 未授权： 监控组件敏感接口暴露（/actuator/env、/actuator/heapdump 等）
  • Fastjson 反序列化： 历史高危漏洞，可导致 RCE
  • Log4j2： 可导致远程代码执行
  • 文件上传： 上传 WebShell
  • SQL 注入： 后端代码过滤不严导致

日志位置： /var/log/ 或应用目录下 logs/

17. OWASP Top 10 有哪些？

答：

  1. 访问控制失效（Broken Access Control）
  2. 加密失败（Cryptographic Failures）
  3. 注入（Injection）
  4. 不安全设计（Insecure Design）
  5. 安全配置错误（Security Misconfiguration）
  6. 易受攻击和过时组件（Vulnerable and Outdated Components）
  7. 身份认证失败（Identification and Authentication Failures）
  8. 软件和数据完整性失败（Software and Data Integrity Failures）
  9. 安全日志和监控不足（Security Logging and Monitoring Failures）
  10. 服务端请求伪造（SSRF）（Server-Side Request Forgery）

18. XXE（XML 外部实体注入）漏洞？

答：

危害： 敏感文件泄露、SSRF、远程文件读取/数据外带、拒绝服务攻击，严重时可配合其他漏洞实现远程代码执行。

利用方式：

  • 读取敏感信息：<!ENTITY xxe SYSTEM "file:///etc/passwd">
  • 盲打 XXE：通过 DNSLog 或外带数据通道回传
  • 攻击内网服务、DDOS 攻击

防御：

  • 禁用外部实体加载（DOCTYPE 禁止）
  • 过滤常见协议头 file://、php://filter
  • 使用 JSON 替代 XML 传输数据

19. CSRF（跨站请求伪造）漏洞？

答：

危害： 盗号、修改个人信息、诱导受害者执行命令。

利用方式：

  • GET 型：构造恶意 URL，诱导受害者访问
  • POST 型：构造自动提交表单，诱导受害者访问或点击
  • 配合存储型 XSS：自动触发，无需用户主动点击

防御：

  • 添加不可控参数：手机验证码、生物指纹、随机 Token
  • 验证 HTTP 头的 Referer
  • 修改密码时要求输入原密码
  • 使用 SameSite Cookie 属性

20. SSRF（服务端请求伪造）如何利用？

答：

利用方式：

  • 读取本地文件：file:///etc/passwd
  • 探测内网：http://192.168.1.1:22、dict://、gopher://
  • 攻击内网服务：Redis、FastCGI、MySQL 等
  • 访问云平台元数据服务（如 AWS 169.254.169.254）

防御：

  • URL 白名单，禁止请求内网 IP、回环地址、链路本地地址
  • 限制协议（只允许 HTTP/HTTPS）
  • 限制端口（只允许 Web 端口）
  • DNS 解析验证，防止 DNS 重绑定绕过

四、红队/渗透相关

16. 外围打点的基本流程？

答：

  1. 靶标确认： 明确目标范围
  2. 信息收集： 子域名、Whois、C 段、旁站、Web 指纹识别
  3. 漏洞探测： 扫描 + 手工测试
  4. 利用漏洞： 优先 Java 反序列化类（Shiro、Fastjson、WebLogic、用友 OA 等）
  5. 获取权限： 获取靶标系统权限和关键数据

17. 横向渗透有哪些命令执行手段？

答：

  • psexec
  • wmic
  • smbexec
  • winrm
  • net use 共享 + 计划任务 + type 命令

18. 域内攻击方法有哪些？

答：

  • MS14-068（域提权）
  • Roasting 攻击（离线爆破密码）
  • 委派攻击（非约束性委派）
  • 基于资源的约束委派
  • NTLM Relay
  • 域委派：把域内用户权限委派给服务账户，让服务账号能以该用户身份在域内活动

19. 不出网情况下如何处理？

答：

  • 使用 socks 隧道
  • CS（Cobalt Strike）直接上线
  • ICMP 隧道（封装数据到 Ping 包）
  • DNS 隧道（通过 DNS 查询传递数据，企业极少封锁 DNS 端口）

20. 木马免杀有哪些方式？

答：

  1. 代码混淆： 加密字符串（AES）、指令重排
  2. 加壳： UPX 压缩或 VMProtect 虚拟化
  3. 内存加载： PE 文件注入合法进程（最有效，不落盘且行为模拟合法进程）
  4. 签名劫持： 伪造微软签名或劫持白名单程序

21. 如何绕过 WAF？

答：

  1. 编码绕过： Unicode/Base64 编码注入语句
  2. 分块传输： HTTP 协议分块发送恶意载荷（绕过正则匹配）
  3. IP 轮替： 代理池切换源 IP 避开速率限制
  4. 利用 WAF 规则盲区： 如 JSON 格式 SQLi
  5. 参数污染、大小写混合、注释符干扰

22. 如何识别 CDN 并找到真实 IP？

答：

识别 CDN：

  • ping 命令观察回显（是否有 CDN 节点域名）
  • nslookup 查询域名解析
  • 超级 ping 工具查看多地解析结果是否一致

绕过 CDN 找真实 IP：

  • 查询历史 DNS 解析记录
  • 子域名可能未使用 CDN
  • 邮件服务器 IP
  • 国外节点访问
  • SSL 证书信息

23. 内网渗透的完整流程？

答：

  1. 前期打点： 攻击处在 DMZ 区，能被互联网直接访问的网站或服务。信息收集、漏洞扫描、漏洞挖掘、历史漏洞利用
  2. 权限获取： 利用 Web 漏洞、钓鱼、弱口令等获取初始权限
  3. 内网信息收集： 内网存活探测、内网凭证获取、权限提升
  4. 构建代理隧道： 内网穿透（FRP、NPS、Neo-reGeorg 等），后续进行跨网段渗透
  5. 横向渗透： 同一内网网段的攻击，获取多台主机权限
  6. 权限维持： 添加后门账号、计划任务、服务、WebShell、内存马等
  7. 痕迹清除： 清理日志、删除临时文件、隐藏进程

24. 漏洞挖掘思路？

答：

信息收集阶段：

  • 子域名收集、端口扫描、指纹识别
  • 发现功能点：登录、上传、搜索、导出、API 接口

测试漏洞阶段：

  • 注入类：SQL 注入、XSS、XXE、命令注入
  • 逻辑类：越权、支付逻辑、验证码绕过、密码重置
  • 配置类：未授权访问、敏感信息泄露、目录遍历
  • 组件类：Fastjson、Shiro、Log4j2、Struts2、SpringBoot Actuator

验证与报告：

  • 确认漏洞可利用性、影响范围
  • 截图留证、编写修复建议
  • 按危害程度分级报告

24. 护网的分组和流程？

答：

三阶段流程：

  • 备战阶段： 资产梳理、减少暴露面、漏洞扫描、渗透测试、弱口令自查

答：

核心四项：监控、研判、处置、溯源

具体工作：

  • 使用 IPS/IDS 等设备做流量监控与日志分析
  • 判断安全事件是否误判
  • 对安全管理中心发出的态势排查单进行排查并反馈
  • 执行封堵/解封工单
  • 每两小时反馈排查结果、设备巡检报告、封堵情况

26. IDS 和 IPS 的区别？

答：

维度 IDS IPS
部署方式 旁路部署（镜像端口） 串联部署
功能 检测攻击行为，产生告警 检测并实时阻断攻击流量
对业务影响 不影响业务，风险低 可能影响业务，误报会导致误拦截
适用场景 需要全面监控但不愿影响业务的场景 需要实时拦截攻击的场景
互补关系 防火墙是第一道防线，IPS 是第二道，IDS 是补充检测

27. EDR 怎么看？

答：

EDR（终端检测与响应）主要看主机行为，不只看文件特征：

  • 可疑进程树： Office、浏览器、Web 服务拉起 shell
  • 异常执行： PowerShell、cmd、bash 异常执行
  • 持久化： 计划任务、服务、自启动项异常
  • 凭据访问： 横向移动、凭据抓取行为
  • 外联异常： 可疑外连、文件落地和加密行为

EDR 对无文件攻击、勒索、挖矿、横向移动比较有价值，但也需要结合日志和流量确认。

28. 态势感知怎么减少误报？

答：

  • 规则调优： 给内部扫描器和监控系统打标签，降低低置信规则权重
  • 资产上下文： 对正常业务参数加白名单，把单点告警改成多条件关联
  • 样本沉淀： 保留真实攻击样本做反向优化，定期复盘误报原因
  • 避免一刀切： 不要为了降低告警量直接关闭高价值规则

29. WAF 怎么部署？

答：

常见部署方式：

  • 反向代理（最常用）
  • 透明代理/串联部署
  • 旁路镜像（只检测不阻断）
  • 云 WAF

部署步骤：

  1. 梳理 Web 资产和业务流量，确认域名、端口、证书、真实源站
  2. 配置 DNS 或负载均衡，让流量先经过 WAF 再回源
  3. 导入 HTTPS 证书，配置域名、回源地址、健康检查
  4. 先开启监控/告警模式，观察规则命中情况
  5. 对正常业务接口做白名单和规则调优
  6. 对高危接口逐步开启拦截策略
  7. 上线后持续复盘误报、漏报和攻击样本

六、网络基础

26. TCP 三次握手与四次挥手？

答：

三次握手：

  1. 客户端发送 SYN → SYN_SENT
  2. 服务器回 SYN+ACK → SYN_RCVD
  3. 客户端发 ACK → 双方 ESTABLISHED

四次挥手：

  1. 客户端发 FIN → FIN_WAIT_1
  2. 服务端回 ACK → CLOSE_WAIT
  3. 服务端发 FIN → LAST_ACK
  4. 客户端回 ACK → TIME_WAIT → CLOSED

27. HTTP 无连接与无状态的含义？

答：

  • 无连接： 每次连接只处理一个请求，处理完收到应答后断开（HTTP/1.1 引入 Keep-Alive 改善）
  • 无状态： 协议对事务处理没有记忆能力，每次请求独立，服务器不保存客户端状态（通过 Cookie/Session 解决）

28. 同源策略与跨域？

答：

  • 同源策略： 域名、协议、端口均相同才算同源
  • 跨域： 浏览器不能执行其它源的脚本，由同源策略造成
  • JSONP： 利用 script 标签 src 属性可跨域，只支持 GET
  • CORS： 支持所有 HTTP 请求类型，通过服务端设置 Access-Control-Allow-Origin 实现

七、安全加固

29. Linux 安全加固要点？

答：

  1. 关闭不必要系统服务
  2. 更改 SSH 默认端口，禁止 root 远程登录
  3. 限制 su 切换 root
  4. 密码复杂度策略（/etc/login.defs）
  5. 检查空口令账号
  6. 禁止 ctrl+alt+del 重启
  7. 禁用 telnet，用 ssh 替代
  8. 设置 hosts.allow 和 hosts.deny
  9. iptables + denyhost 防 SSH 暴力破解
  10. 设置 umask 值 027，登录超时 TMOUT=180

30. Windows 安全基线检查五方面？

答：

  1. 身份鉴别： 更改缺省账户、禁用 Guest、密码复杂性、最小 8 位
  2. 访问控制： 共享账户检查、远程关机授权、授权登录
  3. 安全审计： 登录日志记录、系统日志完备性
  4. 资源控制： 登录超时管理、远程登录超时配置
  5. 剩余信息保护： 不显示上次用户名、关机前清除虚拟内存

八、综合场景题

31. 内网横向攻击如何处理？

答：

  1. 确定攻击来源（是否员工误操作/自动化脚本）
  2. 确定是攻击后，结合时间点查看设备信息、安全事件、进程、流量
  3. 找到问题主机
  4. 应急响应流程：准备 → 检测 → 遏制 → 根除 → 恢复 → 跟踪

32. 如何判断服务器是否被入侵？

答：

网站被攻击表现： 跳转赌博网站、首页被篡改、百度快照被改、被植入 webshell、被 DDoS/CC

服务器被黑表现： 中木马病毒、管理员密码被改、被远程控制、带宽向外发包

排查方法： 分析登录记录、系统日志、web 日志、进程列表、网络连接、启动项

33. Java 内存马如何排查？

答：

  • JSP 注入： 日志中排查可疑 jsp 访问请求
  • 代码执行漏洞： 排查中间件 error.log 可疑报错
  • Servlet/Spring controller 类型： 根据 url 查找日志，确定最早访问时间即注入时间
  • Filter/Listener 类型： 可能有较多 404 带参数请求，或大量不同 url 带相同参数，或页面不存在但返回 200

34. 文件读取漏洞通常读哪些文件？

答：

Linux：

  • /etc/passwd、/etc/shadow
  • /root/.bash_history
  • /root/.ssh/id_rsa（拿私钥直接 ssh）
  • /proc/xxxx/cmdline（进程状态枚举）
  • 数据库 config 文件、web 日志

Windows：

  • C:\boot.ini（系统版本）
  • C:\Windows\System32\inetsrv\MetaBase.xml（IIS 配置）
  • C:\Windows\repair\sam（系统初次安装密码）
  • C:\Program Files\mysql\my.ini（MySQL 配置）

35. TLS 加密过程简述？

答：

  1. 客户端发送随机数 1 和支持的加密算法列表
  2. 服务端确定加密算法，发送随机数 2
  3. 服务端发送数字证书（含公钥），客户端验证证书有效性
  4. 客户端生成随机数 3，用公钥加密后发送给服务端
  5. 双方用三个随机数通过 DH 算法生成对称密钥
  6. 后续通信使用对称密钥加密

36. AI 在安全运营中的作用？

答：

AI 适合做辅助工作，不能替代最终判断（可能误判或编造）。

适用场景：

  • 日志摘要、告警降噪
  • IOC 提取、攻击链整理
  • 报告初稿、规则生成建议
  • 漏洞情报归纳

原则： AI 做初筛和提效，人负责证据校验，关键结论必须回到日志、流量、主机和业务上下文。

37. 怎么和甲方沟通安全事件？

答：

结构化表达：先说结论，再说证据，再说影响和建议。

示例：

“当前某资产出现 SQL 注入攻击告警，证据包括多次参数探测、异常响应长度和数据库报错。建议先临时封禁攻击源，同时请业务确认接口归属和是否为测试流量；若确认漏洞存在，需要尽快参数化修复，并排查数据泄露风险。”

安抚甲方情绪：

  • 先给结论和定心丸，表明已经控制事态
  • 简明扼要同步现状与影响
  • 给出清晰的下一步处置建议和需要配合的事项

甲方情绪失控甩锅时：

“我完全理解您的焦急。护网结束后，我们会出具详细的复盘报告协助您厘清责任。但当前最核心的任务是止损和防守，多拖一分钟内网就多一分风险，我们先把眼前的漏洞补上，您看可以吗？”

38. 后门处理的完整流程？

答：

处理后门的核心是：先保全证据，再定位入口和影响范围，不能只删文件。

常见后门类型： WebShell、内存马、计划任务、系统服务、自启动项、隐藏账号、SSH key、恶意脚本、异常外联程序

处理流程：

  1. 隔离： 隔离受影响主机或限制外联，防止攻击者继续操作
  2. 取证： 保留 Web 日志、主机日志、可疑文件、进程信息、网络连接和告警记录
  3. 定位后门类型：
    • WebShell → 看 Web 目录和访问日志
    • 内存马 → 看 Java 进程、过滤器、监听器、异常类加载
    • 系统后门 → 看账号、服务、计划任务、自启动项和 SSH key
  4. 排查入侵入口： 弱口令、漏洞利用、文件上传、SQL 注入、未授权接口或历史 WebShell
  5. 清理： 删除可疑文件、进程、服务、计划任务、异常账号和外联配置
  6. 修复： 修复入口漏洞，修改相关账号密码，更新组件补丁，收紧权限和出网策略
  7. 持续观察： 恢复后持续观察日志和流量，确认没有复连、复发和横向移动

清后门不是最终目标，必须找到入口并完成加固，否则容易再次被打进来。

39. 0day 没有设备防护怎么分析？

答：

  1. 确认影响： 受影响资产、组件版本、暴露面
  2. 异常检测： 看是否有异常请求、异常参数、异常响应
  3. 主机侧： 关注 Web 服务是否拉起 shell，检查新增文件、异常进程、外连、计划任务
  4. 临时处置： 临时下线或限制访问高风险接口，加 WAF 临时虚拟补丁
  5. 网络隔离： 限制出网和内网访问
  6. 等官方补丁后尽快升级

40. 挖矿应急详细流程？

答：

判断阶段：

  • 查看 CPU 占用率（是否持续高企）
  • 查看流量分析，是否访问可疑网站或下载可疑文件
  • 查看是否有外连远程 IP（矿池地址）

分析阶段：

  • 登录服务器，查看进程是否有异常
  • 查看异常进程的服务项，停止可疑服务
  • 查看计划任务是否有可疑项

处置阶段：

  • 停用并禁止可疑服务项（根据描述寻找）
  • 根据实际木马路径，删除木马文件
  • 重启计算机，使用杀软全盘查杀
  • 修复入侵入口（弱口令、漏洞），检查横向移动
  • 持续观察是否复发

十一、通用流量研判方法论

39. 流量特征分析的通用思路？

答：

从”工具类型 + 流量表现 + 成功证据 + 联动主机证据”四个角度回答。

不要只背工具名，面试时重点说清楚：

  • 请求是否异常（源 IP、目标资产、URL、方法、Header、参数、Body、编码方式、请求频率）
  • 响应是否成功（状态码、响应长度、报错信息、敏感回显、下载文件、时间延迟）
  • 是否有后续攻击链行为
  • 主机侧是否出现进程/文件/外联异常

五步研判法：

  1. 看请求： 确认 payload、编码、访问频率和目标接口
  2. 看响应： 确认是否有报错、敏感回显、响应长度变化或时间延迟
  3. 看上下文： 是否核心资产、是否业务高峰、是否内部扫描器、是否安全测试窗口
  4. 联动主机： 进程、文件落地、网络连接、账号登录、计划任务、服务、自启动、EDR 告警
  5. 判断结论： 真实攻击、攻击成功、攻击失败、扫描探测、内部测试、误报，并给出处置建议

面试表达模板：

“我分析流量特征时不会只看某一个关键字，而是按攻击链判断。第一步看请求包，确认 payload、编码、访问频率和目标接口；第二步看响应包，确认是否有报错、敏感回显、响应长度变化或时间延迟；第三步结合资产重要性和业务场景，判断是不是扫描器、测试流量或真实攻击；第四步联动主机日志和 EDR，看是否有异常进程、文件落地、计划任务、外联或账号登录异常。只有流量证据和主机证据能闭环，才会升级为真实攻击处置。”

十二、面试表达与沟通技巧

40. 面试自我介绍怎么说？

  • 表达学习能力和团队协作意识

41. 被问到不会的问题怎么办？

答：

  • 诚实承认： “这个问题我目前了解不深，但我可以尝试从相关角度分析…”
  • 关联迁移： 把不会的问题引到你会的领域
  • 表达学习意愿： “这部分我确实需要加强，回去后会重点学习”
  • 不要瞎编： 面试官通常能识别出编造的内容

42. 怎么描述一次完整的应急响应经历？

答：

按”时间线 + 关键动作 + 结果”描述：

  1. 发现： 通过什么告警/日志发现异常
  2. 确认： 如何判断是真实攻击（流量证据 + 主机证据）
  3. 遏制： 隔离主机、封禁 IP、阻断横向移动
  4. 根除： 清理 WebShell/后门、修复漏洞、修改密码
  5. 恢复： 验证无残留后恢复业务
  6. 复盘： 输出报告、加固建议、规则优化

43. 被问到溯源案例怎么说？

答：

结构：线索获取 → 关联分析 → 身份定位

示例：

“通过天眼日志发现攻击 IP，然后使用微步查询该 IP 的历史情报和关联域名，发现绑定了一个备案域名。通过域名备案信息查到所属单位。同时分析攻击者上传的 WebShell 样本，发现代码注释中留有 QQ 号，通过社交工程进一步确认攻击者身份。”

要点：

  • 强调合法合规，只做证据链关联，不做未授权反制
  • 突出你的分析思路，而不是具体技术细节
  • 说明最终成果（如提交护网指挥部、获得溯源加分）
